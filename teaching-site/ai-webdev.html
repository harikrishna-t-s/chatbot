Module 01 — Web Dev Basics · 25 min

The Vocabulary Every Beginner Needs

Cover these terms simply, with a real-world analogy for each. Don't panic — you only need to recognise these, not recite them from memory.

🍽️ The Master Analogy: A website = a restaurant. HTML = the building & furniture. CSS = interior design. JS = the staff's actions. Backend = the kitchen. Database = the storeroom. API = the waiter between dining room and kitchen.

Term Simple explanation Restaurant equivalent
HTMLThe skeleton — headings, paragraphs, buttons, imagesBuilding & furniture
CSSThe styling — colors, spacing, fonts, layoutInterior design
JavaScript (JS)The behavior — what happens when you click, scroll, typeStaff actions
FrontendEverything the user sees and touches in the browserThe dining room
BackendLogic, data, security — runs on a serverThe kitchen
DatabaseWhere information is stored permanentlyThe storeroom
APIA waiter between frontend and backend — takes requests, brings dataThe waiter
FrameworkA pre-built toolkit so you don't start from zero (e.g. React, Next.js)A franchise kitchen manual
Hosting / DeploymentPutting your site on a server so anyone can visit itOpening the restaurant to the public
Domain nameThe address people type (e.g. mysite.com)The restaurant's street address
Git / GitHubVersion-controlled storage for your code — tracks every changeThe manager's daily log
Responsive designSite adapts to phone, tablet, laptop screens automaticallyTables that rearrange for different party sizes

Module 03 — Frontend Structure · 15 min

The Shape of Almost Every Web Project

AI-generated code can look overwhelming. Knowing the standard folder structure removes that fear instantly.

Plain Path

HTML + CSS + JavaScript. Perfect for a single simple page — no setup, open in any browser, AI tools can generate it in seconds.

my-site/
├── index.html
├── style.css
└── script.js

Modern Path ⭐

Next.js (React framework) + Tailwind CSS — what most AI builders (v0, Lovable, Bolt) generate by default. Worth knowing the names.

my-app/
├── app/          → pages
├── components/   → reusable pieces
├── public/       → images, icons
└── package.json  → project config

Tip: When you open AI-generated code for the first time, ignore the files you don't recognise and focus on just two things: index.html (or page.js) for content, and the CSS file for styling.

Module 04 — Backend & Databases · 15 min

You Rarely Need to Build a Backend From Scratch

Modern AI-friendly tools give you a database, authentication, and storage with zero server management. Here's the landscape.

Need AI-friendly Tool What you get
Database + Auth + Storage Supabase ⭐ Instant Postgres database, login/signup, file storage — all via a visual dashboard
Alternative to Supabase Firebase Google's version — real-time database, auth, hosting. Well-documented.
Custom backend logic FastAPI (Python) or Node.js/Express Full custom backend — write your own routes and logic with AI help.
Small backend tasks Vercel Functions, Supabase Edge Functions Run short server-side snippets without managing any server.

Simple rule of thumb: "If your site just needs to save form submissions, user logins, or simple data — use Supabase or Firebase. Only go custom (FastAPI / Node) once you have specific complex logic."

Module 05 — CLEAR Prompting · 20 min

How to Talk to AI — The CLEAR Framework

This is often the most valuable part of the session. The difference between a useless and a perfect AI response is almost always the quality of the prompt.

C

Context

Tell the AI what project you're working on, what stack it uses, and what already exists. "I'm building a Next.js portfolio site" is vastly better than nothing.

L

Language / Level

Say you're a beginner. Ask it to explain, not just output code. "I'm new to CSS — please explain the change you make."

E

Exact Ask

One specific outcome per prompt, not five vague ones. "Fix only the mobile spacing" is specific. "Make it better" is not.

A

Ask for Alternatives

"Give me 2 ways to do this" when you're unsure which approach to take. Options help you understand trade-offs.

R

Review & Refine

Never accept the first output blindly. Ask "what did you just do and why?" after every response.

Good vs. Bad Prompts — Side by Side

❌ Vague

"Make my website better"

→
✅ CLEAR

"My navbar overlaps my hero text on mobile screens under 400px width. Here's my code [paste]. Fix only the mobile spacing, don't change anything else, and explain the CSS change you made."

❌ Vague

"Add login"

→
✅ CLEAR

"Add email/password signup and login using Supabase Auth to my Next.js app. Show me exactly which files to create and where to put my Supabase keys safely — not hardcoded."

Bonus prompting tips:

  • Paste the actual error message, don't paraphrase it
  • Ask AI to work in small steps: "do only step 1, wait for me to confirm"
  • Ask "what could go wrong with this approach?" before big decisions
  • Keep one conversation per feature — consistent context = better results

Module 06 — Debugging · 15 min

Don't Panic. Read the Error.

Most people panic at errors. After this module, you'll feel calm — because you have a loop to follow.

  1. Don't panic — read the error message first

    It usually tells you the file name and line number. That alone narrows the problem to one place in the code.

  2. Open browser DevTools (F12 → Console tab)

    Right-click anywhere → Inspect → Console. Red text = JavaScript errors. This is your live error feed.

  3. Copy the exact error text

    Don't paraphrase it. Copy it character-for-character, along with the relevant 5–10 lines of code around the problem.

  4. Give it to your AI tool with context

    Paste: "I got this error: [error]. Here's the code: [code]. What does this mean and what's the simplest fix?"

  5. Change ONE thing at a time

    Don't let AI rewrite everything when only one line is broken. Targeted fixes are easier to understand and reverse.

  6. Verify the fix makes sense

    Ask the AI to explain what it changed and why. If it can't explain it clearly, don't trust the fix blindly.

Common Beginner Errors Decoded

Error messageWhat it really meansWhere to look
404 Not FoundThe URL/file path you requested doesn't existCheck spelling in the URL or file name
undefined is not a functionYou called something that doesn't exist — usually a typo or missing importCheck the variable name and where it's imported
CORS errorFrontend and backend are on different domains/ports and blocking each otherAdd CORS headers to the backend response
Failed to fetchThe API endpoint isn't running, or the URL is wrongCheck the backend is running and the URL matches exactly
SyntaxError: Unexpected tokenA typo broke the structure of your code (missing bracket, comma, quote)Look at the line number in the error
401 UnauthorizedMissing or invalid API key / auth tokenCheck your .env file and API key header

Module 07 — UI/UX · 15 min

Designing for Real Users — 6 Principles

Keep this practical, not theoretical. A user should never look at your site and wonder "what do I click?"

🎯

Clarity over Cleverness

A user should never wonder "what do I click?" If a button needs an instruction manual, redesign the button.

🔄

Consistency

Same button style/color = same type of action everywhere. Don't make users re-learn your interface mid-session.

💬

Feedback

Every click/tap should visibly respond. Loading spinners, color changes, confirmation messages — users need to know something happened.

⬜

Whitespace

Breathing room improves readability. Don't cram content. Whitespace is not wasted space — it guides the eye.

📱

Mobile-First

Design for the small screen first. Most users are on phones. Then scale up, not down.

♿

Accessibility

16px+ body text, high color contrast, alt text on images. Not optional — it's what makes your site usable for everyone.

Module 08 — Idea → Live Website · 20 min

The Full Path from Idea to Live on the Internet

Walk through this as one continuous story. Every step corresponds to a real action you'll take. Tick them off as we go!

1

Define the idea in one sentence

e.g. "A one-page portfolio for a photographer with a gallery and contact form."

2

Plan with an AI chat assistant first

Ask Claude or ChatGPT to break the idea into pages, features, and rough sections — before touching any builder tool.

3

Generate the frontend

Use Lovable, Bolt.new, or v0 with a clear prompt describing pages, sections, and style/mood.

4

Review the generated structure

Open the file tree, ask AI to explain what each part does. Don't just accept it — understand it.

5

Add backend / database if needed

Connect Supabase or Firebase for forms, auth, or stored data. Follow their "quickstart" docs with AI's help.

6

Test locally

Click through every button and form. Break things on purpose. What happens when you submit an empty form?

7

Debug with the Module 6 loop

Something broke? Read the error, paste it into Claude with context, fix one thing at a time.

8

Polish UI/UX

Apply the 6 Module 7 principles. Ask AI: "Is this mobile-responsive? Is the contrast accessible?"

9

Deploy to Vercel or Netlify

Push to Vercel or Netlify for a free live link in minutes. Connect a custom domain if desired.

10

Share and gather feedback

Send the live link to 2–3 real people. Note what confuses them. Iterate. That's the full loop.
